# Tasks — assertions
> Deterministic invariants that gate every state-changing action (`AGENTS.md`, The one law). An action that fails an assertion is rejected with its exit code, writes no state and emits no event, and the core stays up.

- Precondition: every request is rejected (exit 2) unless `op` is one of `add`, `list`, `show`, `update`, `delete`, `comment.add`, `comment.edit`, `comment.delete` and every other field is one that op takes, with its type: ids positive integers, `status` one of the seven states, `priority` an integer within ±1000000, `owner` and `author` lowercase names, `title` one line of valid UTF-8 within `tasks.title_max_bytes`, `body` a JSON object within `tasks.body_max_bytes`, comment `text` valid UTF-8 within `comments.text_max_bytes`.
- Precondition: `add` and `update` are rejected (exit 3) unless `parent` is `null` or an existing task, and `update` is rejected (exit 4) when the new parent is the task itself or one of its descendants.
- Precondition: `delete` is rejected (exit 4) while any task names it as `parent`; `comment.delete` is rejected (exit 4) while any comment replies to it; `comment.add` is rejected (exit 4) when `reply_to` belongs to another task.
- Precondition: every operation is rejected (exit 5) unless the merged config passes validation and `KOMBINAT_DATA` names an existing directory.
- Invariant: every change commits in one transaction and is followed by exactly one `tasks.*` event whose subject is `task/ID`; an unchanged `update` or `comment.edit` writes nothing and emits nothing; check: `kombinat --json log --tail 2 | jq -r '.[1].payload.events'` prints `1` after a change and `kombinat --json log --tail 1 | jq -r '.[0].payload.events'` prints `0` after a read.
- Invariant: no event line is rejected for size; a payload over 60000 bytes falls back to a lean one; check: `kombinat --json log --tail 1 | jq '.[0].payload.events_rejected'` prints `null`.
- Invariant: ids are never reused and the api entrypoint prints exactly one JSON document, success or failure; check: `printf '{"op":"show","id":1}' | kombinat module run --entrypoint api --stdin tasks | jq -e 'has("ok")'`.
- Fallback: on assertion failure — the transaction rolls back, the answer carries `ok: false` with the error code and message, the exit code says which assertion failed, and only the core's `core.module.run` records the attempt.
